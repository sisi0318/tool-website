## 优先修复的五项问题

### A01 · P1：离开画布后再次发送同一个 POST

**位置：** `lib/canvas/store.ts:116`、`lib/canvas/store.ts:1192`，卸载调用位于 `app/canvas/canvas-content.tsx:35`。

保持默认自动运行，添加一个延迟响应的 HTTP Tester（POST），点击一次运行全部节点，随后在响应返回前离开画布。实测同一 `audit-only` 请求体发送两次，第二次发生时页面已在 `/tools`。测试请求全部由本地拦截处理。

卸载只增加执行版本，未停止正在进行的请求；整图执行又将版本变化当成需要重新计算，保留了运行手动节点的授权。应在卸载时中止执行，并确保自动重算不能重放已经执行过的手动网络节点。**仅修离页取消还不够，也应覆盖执行期间编辑图导致的重试。**

证据：`workflows/browser-results.json` 中 `unmountPostRerun`、`post-replayed-after-leaving-canvas.png`。

### A02 · P1：取消查询参数勾选后，参数仍被发送

**位置：** `app/tools/http-tester/page.tsx:825`、`lib/http-request-tools.ts:26`。

输入 `https://example.com/?token=synthetic-token`，等待参数同步，取消唯一参数的勾选后发送。界面为 `unchecked`，捕获到的请求 URL 仍含该 token。

没有启用参数时同步函数提前返回，最终 URL 合并也只删除启用参数的旧值。需要用完整参数表统一重建 URL，覆盖取消最后一项、删除最后一行和重复参数等情况。

证据：`network/http-ui-controls.json`、`http-disabled-param.png`。

### A03 · P1：PDF OCR 静默丢弃大图并导出完全空白页

**位置：** `lib/pdfjs-runtime.ts:10`、`lib/pdf-ocr-client.ts:23`、`lib/pdf-ocr-client.ts:42`。

合法单页 PDF 只有 **225,465 字节**，内嵌一张 **5000×5000** 的扫描图。上传成功，但 PDF.js 的 `maxImageSize: 20_000_000` 在渲染前直接移除该图，界面仍允许成功导出可搜索 PDF。

导出文件只有 **9,134 字节**。使用独立 PDFium 渲染和 pypdf 图像提取确认：源图包含颜色及文字，导出图像三个 RGB 通道的极值全部为 `[255,255]`，确实是白页，不能归因于 OCR 识别不准。

应受控地解码、降采样大图；如果当前资源边界不支持，必须明确拒绝并阻止缺图页面成功导出。不能简单取消全部资源限制。

证据：`image-pdf/large-scan.pdf`、`large-scan-output.pdf`、`pdf-independent-evidence.json` 及两个 PDF 的独立渲染 PNG。

### A04 · P1：旅程导入画布会覆盖旧草稿，且无法撤销

**位置：** `lib/journey/to-canvas.ts:110`，调用处 `app/journey/page.tsx:479`，画布加载清空撤销栈位于 `lib/canvas/store.ts:1351`。

画布已有自动保存但尚未另存为命名工作流的内容。在另一份数据旅程中点击“在画布中打开”，`canvas-state` 被直接覆盖；没有确认或恢复点，进入画布后撤销禁用。

建议使用待导入槽位，让用户选择追加或替换；替换保留恢复点，保护已有未命名草稿。

证据：`workflows/browser-results.json` 中 `canvasOverwrite`、`journey-overwrote-existing-canvas.png`。

### A05 · P1：cURL 导出丢失方法参数的引号，改变 shell 执行语义

**位置：** `app/tools/http-tester/page.tsx:436`，方法输入来自 `lib/http-request-tools.ts:123`。

导入一个方法参数包含分号、但原本被引号包裹的合成 cURL 样例，导出时方法被直接拼接成未引用文本。安全的单参数边界消失，导出的字符串被 PowerShell 解析器识别为两条命令：`curl -X GET` 和 `ECHO AUDIT_MARKER`。

**浏览器不会自动执行这些命令；风险发生在用户复制并执行导出结果时。** 本轮只捕获字符串并解析语法树，没有执行测试 marker 命令。应校验 HTTP 方法，并对所有插入 shell 的参数保留正确引用。

证据：`network/curl-ui-method.txt`、`curl-ui-method.png`、`root/curl-shell-ast.json`。

## 已知局限和待验证事项

这些不计入上述 14 项新增确认清单：

- 宽图跨 OCR 裁片的长句发生部分重复、截断，且置信度约 99%。1800px 宽对照正常，3000px 宽样例将两行变成四行。[[tools/02-browser-ocr]] 已披露极宽跨块长句局限；本轮补充了具体损坏证据，建议增加跨缝合并或边缘复核标记。
- PDF OCR 取消或单页失败后不保留这轮已完成页、表格重建覆盖既有编辑，都已经在当前界面/文档中说明，因此作为能力改进而非未披露缺陷。
- 旧 CSV 页面默认动态数值转换，而新 CSV 模板显式保留文本；建议在独立工具页暴露相同选项。公式形态文本也可增加可选择的表格安全导出模式，兼顾原文保真。
- 画布最后 300ms 编辑可能未保存、JSON Stringify 的 `null` 处理存在源码级定向记录。本轮没有补做真实页面验证，保留在子报告附注，后续先复现再决定修复。
- Markdown 外部资源加载只完成源码检查，未作为确认缺陷计数。
