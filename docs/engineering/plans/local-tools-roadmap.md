# 本地工具与交互增强

按可独立验证的功能分批提交。已有页面、画布节点和数据旅程应复用同一处理函数；新增文案提供中英文，文件处理不上传用户数据。

## 实施顺序

1. Protobuf 深度检查器
   - [x] 公共编解码内核、大整数精度、重复字段、错误偏移、画布 Schema 编解码
   - [x] 字段元数据、Hex 联动、无 Schema 字段解释切换
2. [ ] JSON/YAML 结构化 Diff：路径差异、忽略字段、数组按键对齐
3. [ ] 结果继续处理：工具输出／子树送入数据旅程，保留二进制类型
4. [ ] JSON 树：紧凑视图、按层展开、搜索、复制路径、聚焦子树
5. [ ] 文件压缩：ZIP 目录、选择性提取、多文件打包、二进制下载
6. [ ] CSV/JSONL 日志：筛选、排序、分组计数、错误行和结果导出
7. [ ] Unicode 字符检查：码点、UTF-8、不可见字符和规范化
8. [ ] 文本行处理：去重、排序、空白清理、前后缀、列提取和集合操作
9. [ ] URL 参数编辑：拆解、重复参数、解码和重新组装
10. [ ] MessagePack/CBOR：浏览器本地编解码和特殊类型表示
11. [ ] SQLite：本地文件、表结构、查询和数据导出
12. [ ] PDF：合并、拆分、重排、旋转、图片生成和页码

## Protobuf 内核

`lib/protobuf-tools.ts` 同时供页面和适配器使用。无 Schema 结果中，安全范围内的整数仍为 number，超出的整数为十进制字符串；有 Schema 的 64 位整数按 Protobuf JSON 规则表示为字符串，bytes 表示为 Base64。无 Schema 编码不猜测数字字符串的类型，精确的 int64/uint64 编码应提供 Schema。

画布无 Schema 输出保留 `field_1` 等原有根键，新增 Hex 输出端口。嵌套类型识别只接受完整合法的消息；非法根消息报告错误及字节偏移，不返回部分成功结果。处理设有字节数、字段数、递归深度及分析工作量上限。

检查器按每次字段出现的位置保存解释选择，支持有符号整数、ZigZag、浮点数、UTF-8、Base64 字节、嵌套消息和 packed 数组。字段和 Hex 可双向定位，标签与载荷分别高亮；可复制字段或载荷 Hex，下载原始载荷。字段与字节分页显示，失败的类型切换保留原结果。Schema 模式只检查 wire 数据，上方 JSON 始终遵循 Schema。
