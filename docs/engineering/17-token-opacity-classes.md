# 给颜色令牌加透明度的类名

画布改版时发现的（[[16-canvas-floating-chrome]]），那次只改了画布目录。这一篇是全站的处理。

## 问题

`tailwind.config.ts` 里的 `md-*` 颜色是裸的 CSS 变量：

```ts
"md-primary": "var(--md-sys-color-primary)"
```

变量里是十六进制颜色，Tailwind 3 没法往里塞透明度。于是下面两种写法**整条规则都不生成，也不报警告**：

```
bg-md-surface-container/95
hover:bg-[var(--md-sys-color-on-surface)]/[0.08]
```

发现时全站 210 处、72 个文件（画布 50 处已在上一轮改掉）。它们不是装饰：

- 画布的四个对话框和 M3 底部抽屉**没有遮罩**；
- 顶栏、底部导航、工具页的路径栏的“半透明底色”其实是**完全透明**，只剩一层模糊，内容从后面滚过去时文字叠在一起；
- 通用按钮（`components/ui/button.tsx`）有六种样式的**悬停底色不出来**（其中四种只剩悬停时的阴影）；工具列表、顶栏、标签页里的悬停和按下反馈也没有；
- 错误提示、选中项、拖放区的浅色底和描边没有；
- 首页的两团背景光晕没有。

## 做法

### 令牌改成函数颜色

`lib/m3/tailwind-color.ts` 的 `tokenColor(name)`。Tailwind 会把它想要的透明度传进来：

| 类名 | Tailwind 传入 | 生成 |
|------|--------------|------|
| `bg-md-primary` | 它自己的 `var(--tw-bg-opacity, 1)` | `var(--md-sys-color-primary)`，和以前一样 |
| `bg-md-primary/90` | `0.9` | `color-mix(in srgb, var(--md-sys-color-primary) 90%, transparent)` |

没加透明度的类名输出不变（只多一行 `--tw-bg-opacity: 1`），所以这次改动不会影响那几千处正常的用法。

不支持 `color-mix()` 的浏览器（Chrome 111、Safari 16.2、Firefox 113 之前）会丢掉混色的那条声明，效果和改之前一样：没有悬停层、没有浅色底。**没有用 `<alpha-value>` 占位符的写法**：那样连不带透明度的类名也要经过 `color-mix()`，旧浏览器会丢掉全部颜色。

### 任意值写法改成令牌

`bg-[var(--md-sys-color-primary)]/90` 走不到上面的函数，仍然不生成规则。全站 144 处统一改成 `bg-md-primary/90`。其中 on-surface 的状态层用上一轮加的别名：

```
hover:bg-md-hover      /* on-surface 8% */
active:bg-md-pressed   /* on-surface 12% */
```

### 不在刻度上的透明度写成方括号

还有第三种不生成规则的写法：透明度不在 Tailwind 的刻度上。刻度只有 5 的倍数（本项目另补了 38），`/98`、`/92` 不算数。顶栏滚动后的底色（98%）和工具页路径栏（92%）就是这样，改成 `/[0.98]`、`/[0.92]`。

这两处是对着截图才发现的：令牌和写法都改对了，顶栏在截图里却和改之前一个像素不差。

### 测试挡住回潮

`lib/m3/tailwind-color.test.ts` 扫 `app`、`components`、`hooks`、`lib`：

- 不许出现 `xxx-[var(--…)]/透明度`；
- 带透明度的 `xxx-md-名字/…`，名字必须是主题里用 `tokenColor()` 声明的令牌（`md-hover/50` 这类给别名再加透明度的同样不生成规则）；
- 不带方括号的透明度必须在刻度上。

## 没有照原样生效的五处

其余的都是“写的是什么，现在就显示什么”。这五处如果照原样生效会变差：

- **三处小字的调淡去掉了**：错误页的 digest（`/70`）、分支抽屉里选中项的摘要（`/70`）、“输入已丢失”卡片的说明（`/80`）。它们以前不生效，文字一直是满强度的；真让它生效，对比度就往下掉。现在写成不带透明度的令牌，和改之前看起来一样。
- **旅程建议芯片里的识别类型标签不垫底色**（原来写的是 15% 的 secondary）。10px 的字在 secondary-container 上的对比度本来就贴着 4.5，底色一生效掉到 4.07，无障碍扫描报了出来。
- **工具页“添加工具”面板里的格子**：本身有底色，悬停层一旦生效会把底色整个换成 8% 的 on-surface。改成悬停和按下时往上提一档表面色。

逐个看过其余带悬停层的元素（37 处），底色都是透明的，或者悬停层和底色在互斥的分支里。

## 看得出变化的地方

| 位置 | 以前 | 现在 |
|------|------|------|
| 顶栏、底部导航、工具页路径栏 | 透明 + 模糊，后面的内容糊成一团透上来 | 92–98% 的表面色 + 模糊 |
| 所有按钮、图标按钮、列表行 | 悬停、按下没有反馈 | 有 |
| 首页 | 纯色背景；吉祥物标签上的圆点套着一圈蓝色（Tailwind 的默认描边色） | 标题后面两团浅色光晕；吉祥物的标签有底色，圆点外圈是主色 |
| 错误提示、确认条 | 只有文字 | 浅红底 + 红色描边 |
| 选中的缩略图、拖放区、搜索命中的 JSON 行 | 只有描边或没有标记 | 浅色底 |
| BMI 的分级条 | 肥胖 I、II 级两段是空的 | 55%、75% 的红色 |
| M3 底部抽屉 | 没有遮罩，把手看不见 | 有 |
| 输入框占位文字 | 浏览器默认的灰色 | 50–60% 的 on-surface-variant，随主题变 |

## 验证

- 全站 e2e 的无障碍扫描（每个页面的首屏，浅色和深色各一遍）报出一处，就是上面的识别类型标签；改掉后 327 条全过。
- 扫描覆盖不到的是操作之后才出现的元素（错误提示、选中项）。这些逐个看过：浅色底上的文字都是 on-surface 或对应的 on-…-container，对比度是令牌本身保证的。
- 改动前后的截图在 `.claude/screenshots/site-before-*` 和 `site-after-*`（不入库）。

## 以后写样式

- 给令牌加透明度：`bg-md-primary/90`、`border-md-outline-variant/60`。透明度不是 5 的倍数时写方括号：`bg-md-surface/[0.92]`。
- 悬停和按下：`hover:bg-md-hover`、`active:bg-md-pressed`。元素自己有底色时不要用这两个，换一档表面色或者同色的 `/90`。
- 不要写 `bg-[var(--md-sys-color-…)]/…`，测试会拦。
- 正文和小字不要调淡，用 `on-surface-variant` 这类本来就浅一档的令牌。
