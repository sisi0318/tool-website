# PDF 扫描件 OCR

`/tools/ocr` 的 PDF 模式与 `/tools/pdf` 的扫描件 OCR 共用 `PdfOcrPanel`。使用 [[02-browser-ocr]] 的模型，文件、渲染图片和文字都只在本地处理。图片/PDF 模式切换保留已完成的数据，同时取消隐藏面板中的任务。

PDF.js 按选定页码顺序逐页渲染，处理原始 CropBox、Rotate、UserUnit 和用户旋转。支持 144/200/300 DPI，每页最多 800 万像素、累计 1.2 亿像素；单次最多识别 30 页。来源沿用 PDF 工具的 64 MB / 500 页限制。渲染背景为白色，保存无损 PNG；单次图像总量上限 60 MB，导出 PDF 上限 64 MB。过大页面自动降低采样比例，达到总量上限时要求减少页数。

`createOcrSession` 在连续页面间复用同一个模型 Worker，只允许一个请求运行。单图 API 用该会话完成一次后释放，PDF 则在最后一页完成后释放。取消、错误、卸载、单页识别超时都会终止 Worker。PDF 加载/渲染各有 30 秒上限，导出 Worker 有 60 秒上限；任务版本号阻止过时结果写回。

输出由所选页的静态图像与不可见文字层组成。页面的交互式表单、数字签名、书签和链接不复制进新文件。UI 在运行前明确说明该行为。已有文字层不复制，避免对同一内容重复检索。逐行校对修改文字而保留识别框，TXT、JSON、继续处理与新生成的 PDF 使用同一份校对文本；再编辑会移除旧 PDF 下载地址。

文字层使用 PDF Type 3 空白字形和 `Tr=3`，每组 255 个 Unicode 字符配一个 ToUnicode CMap，支持中文、英文和 UTF-16 代理对。文字矩阵把每行映射到识别四边形；文字可选择和搜索，但不会改变图像像素。不需要下载额外中文字库，不宣称 PDF/A 合规或恢复原始字体。删空某行后，该行不写入文字层；没有识别结果的页面仍保留图像。

测试使用 PDF.js 独立读取混合 Unicode、多字体分组和空白页，并覆盖页序、校对后导出、过期结果、取消与会话复用。QA 样本经 pypdf 提取，Poppler 渲染含/不含文字层的同一图像，两页像素差均为零。实际浏览器回归覆盖两页中英扫描件、模型仅加载一次、移动布局和下载后文字提取。
