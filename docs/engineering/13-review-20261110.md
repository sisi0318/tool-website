# 复查与修复：2026-11-10

源码快照为 `ac40136`。[[12-operations-audit-20260925]] 的五批改动落地之后，10-08 与 10-14 又有 8 个提交直接进了 main，没有经过审查。这一轮先确认现状，再修复。修复在分支 `fix/review-20261110` 上，一项一个提交。

## 复查时的状态

main 的 CI 从 2026-10-08 起连续失败，原因有三个，互不相关：

| 失败的步骤 | 原因 |
|---|---|
| 单元测试 | `app/tools/json/page.test.tsx` 8 条全挂。JSON 页新加的 `SendToMenu` 要 `useRouter`，测试没有 mock；补上之后还有 3 条挂，因为格式化、清空、折叠在标记里各出现两次 |

| 依赖安全审计 | 运行时依赖里攒出 2 个 critical（dompurify、next）、3 个 high（sharp、brace-expansion、source-map-js） |

Vercel 不看 CI 状态，红着也照常部署，所以下面的问题当时都在线上。

## 新增的防线

- **文案键存在性测试**（`lib/translations/translations.test.ts`）。原有用例只保证中英的键对齐、每个 `useTranslations` 的命名空间存在，没有检查调用处传的键。新用例扫描每个 `const t = useTranslations("ns")` 之后写成字面量的 `t("key")`，全站三千多处。R01 和 R06 的 5 个键就是这样找出来的。运行时拼出来的键查不了。
- **工具数量测试**（`lib/tool-registry.test.ts`）。首页是客户端组件，为了一个数字引入整份目录不划算，所以文案里仍是写死的数字，由测试对照 `TOOL_CATALOG.length`。新增工具后这条会失败，提示去改 `home.eyebrow`。
- **手机端 e2e**。JSON 页新增一条：每个基础操作只能有一个可见按钮，工具栏不能出现键名。

## 几项取舍

- **窄屏重复按钮留哪一组**：留 10-14 新加的那组，离输入更近，不用滚过输出区。
- **Service Worker 预缓存不动**。首次访问会在后台下载约 430 个文件、压缩后约 4.5 MB，换来没打开过的工具也能离线使用。维护者确认保留。
- **CSP 拆成两份**。`object-src`、`base-uri`、`form-action`、`frame-ancestors` 四条改为强制：站内没有 `<object>`、`<embed>`、`<base>`，也没有提交到站外的表单。其余继续 Report-Only，原因是 `script-src` 必须放开内联与 eval，强制了也挡不住多少；`connect-src` 照现在的写法会弄坏画布 HTTP 节点和 WHOIS，它们从浏览器直连用户填的地址。
- **jszip 没有换成 fflate**。`lib/zip-tools.ts` 的 `createZip` 有总量 128 MB 的上限并拒绝重名，图片转换和表情包切图现在没有这些限制，直接替换会让大批量打包多出失败情形。jszip 是按需加载的，留着只多占预缓存里约 30 kB。

## 没做的事

- **分享图 `public/og.jpg` 还写着「30+ 个实用工具」**。文字是画在图里的，需要重新出图。
- **让红的 CI 拦住部署**。需要在 GitHub 上给 main 加分支保护，或在 Vercel 上配置忽略构建的条件，属于仓库设置，由维护者决定。
- **HTTP 测试依赖第三方代理 `web-proxy.apifox.cn`**。自建代理意味着要防 SSRF 和滥用，也会产生费用；先直连、失败再走代理是一个新功能。两条路都需要先定方向。
- **大版本升级**：Next 16、React 19、Tailwind 4、next-pwa 换 Serwist。最后一项能清掉那 7 个 low。
- **`/journey` 首屏 314 kB**，全站最重；9 月压到过 267 kB，之后的功能又加了回来，没有逐项归因。
- **crypto-js 整包引入**。加密页用到它的大部分算法，按模块拆分预计省得不多，没有实测。
- **manifest 的 `share_target` 与 `file_handlers`**、**JSON-LD 结构化数据**、**新工具**。都是新功能，没有放进这一轮。
- 开发依赖里还有 6 个 moderate 级公告，不在 CI 的门槛内。
