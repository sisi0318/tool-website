# 工具画布改版：浮动界面

改的是画布周围这一圈界面和几种操作方式。节点卡片内部（每个参数一行、各带端口）、执行引擎、存储格式都没动，已保存的工作流照常打开。

布局和交互参考了即梦的 AI 画布（同样基于 React Flow）：整屏画布、四角的浮动工具条、双击添加、右键菜单、选中节点上方的工具条。颜色、图标、字体、圆角用的仍是本项目的设计令牌，没有搬对方的外观。

## 改版之前的问题

- **两条固定面板占掉将近一半宽度。** 左边节点库 288px 一直在，选中节点时右边属性面板再占 288px：1280 宽的屏幕上画布只剩 704px。
- **加一个节点要绕路。** 去左边找到它，点一下它出现在画布中央，再拖到想要的位置；或者从列表里拖过来。
- **工具条把不相干的东西排成一行**：运行、单步、自动运行、撤销、重做、适应、排列、日志、清空，外加状态文字。
- **工作流的新建、保存、读取、导入导出**在节点库顶上的一个折叠区里。
- **没有右键菜单**，复制、副本、删除只能靠快捷键或属性面板里的按钮。
- **连线一律同样粗细深浅**，节点一多看不出哪几条和手上这个节点有关。

## 现在的样子

画布占满整个窗口，其余都浮在上面：

| 位置 | 内容 |
|------|------|
| 左上 | 返回、工作流名称（点开是新建 / 保存 / 另存为 / 读取 / 导出 / 导入 / 清空）、节点数和保存状态 |
| 左侧 | 节点库竖栏：搜索、常用（收藏与最近）、八个分类。点一格在旁边展开那一类的节点 |
| 右上 | 运行（或停止）、单步、自动运行、运行状态、执行日志 |
| 左下 | 撤销、重做、小地图开关、自动排列、缩放百分比（点开是缩放菜单） |
| 右侧 | 属性卡片，只在选中一个节点时出现，可以关掉 |

小地图默认收着，打开过会记住。空画布中央提示“双击画布，添加节点”。

**手机上**（1024px 以下）：节点库竖栏收成右下角的「节点库」按钮，列表从左侧滑出；属性卡片是底部抽屉，要从节点工具条上的「属性」点开；右上角只留运行和日志，单步与自动运行收进“更多运行选项”，否则工作流名称只剩两三个字。

## 新的操作

- **双击空白处**：在光标位置弹出节点菜单，打开就能打字搜索，回车添加第一项，上下键换一项。节点加在双击的位置。画布不再因为双击而放大。
- **右键菜单**：空白处是添加节点、粘贴、全选、撤销、重做、自动排列、适应画布；节点上是运行到此、添加下一步、复制、副本、停用 / 启用、属性、删除。右键点在一组选中的节点里，菜单对整组生效；点在别的节点上会先改选它。按住右键拖动仍然是平移，不弹菜单。
- **选中节点时它上方有一条工具条**：运行到此、副本、停用、属性、删除。
- **节点右侧的“+”跟着鼠标走**。鼠标移到节点上它就出现；进到节点右边那一条里，它滑到鼠标所在的高度。点一下是能接在这个节点后面的节点列表，选了就加上并连好线；按住拖是从节点的运算结果拉出一条连线。选中的那个节点上它一直显示。
- **缩放菜单**：放大、缩小、适应画布（Shift+1）、缩放至选中节点（Shift+2）、50% / 100% / 200%。
- **右键粘贴落在右键的位置**；Ctrl+V 仍然落在视口中央。
- **和选中节点相连的连线是实色**，其余调淡；正在传数据的、鼠标指着的也是实色。选中的节点多一圈光晕。

原有的快捷键都还在：Ctrl+K 或 / 打开节点搜索，Ctrl+S 保存，Ctrl+C / V / D / Z / A，Delete。

## 几个设计决定

### 浮动界面是画布的兄弟节点，不是 React Flow 的 Panel

`Canvas.tsx` 里 `<ReactFlow>` 之外并排放着顶栏、节点库、视图条、属性卡片，各自绝对定位。放进 React Flow 的 `<Panel>` 的话，面板里的滚轮会缩放画布，要逐个加 `nowheel`；快捷键也要逐个排除。放在外面，画布的手势根本收不到这些元素上的事件。

只有三样在 `<ReactFlow>` 里面：小地图、底部的提示条、节点工具条（`NodeToolbar` 要读节点的位置）。

### 节点库的数据放在画布这一层

`use-node-library.ts`：全部节点、收藏、最近使用、搜索。左侧节点库、双击菜单、“+”三个入口用的是同一份，在哪边加过节点，另外两边的“最近使用”都跟着变。以前这些状态在节点库组件自己手里。

### 节点右侧的“+”是一整条区域，不是一个按钮

第一版的“+”是选中节点后固定在右侧中点的一个小圆，只能点。即梦的做法是节点两侧各有一块看不见的热区，“+”在热区里被鼠标吸着走。照这个思路改了（`nodes/NodeAppendZone.tsx`），我们的节点比它高得多，所以热区是右边一整条：

- **跟随不经过 React。** 鼠标每动一下都要更新位置，直接把百分比写到元素的 CSS 变量（`--append-x` / `--append-y`）上，样式里用它定位。
- **在屏幕上一样大。** “+”画在节点里，会跟着画布缩放。画布外层有一个 `--canvas-counter-scale`（1 ÷ 缩放比例），样式里乘回去；它由视口变化的回调直接写样式，缩放时不重渲染任何节点。
- **拖线是把按下转交给真正的端口。** 在这条区域里按下鼠标时，向节点的主输出端口派发一次同坐标的 `mousedown`。React Flow 要移动超过 1px 才开始连线，所以接着拖就是从那个端口拉线，和直接拖端口完全一样（落在空白处照样弹节点列表）；原地松开它什么也不做，由点击去打开列表。这样不用在节点里放第二个同名端口（连线的锚点和现有的选择器都按端口 id 找），也不用自己实现一遍拖线。
- **“主输出”有运算结果就用结果**（`getPrimaryOutput`），和“加在已选节点后并连接”是同一个原则。
- 这条区域从节点边缘往外 8px 才开始，让出边缘上那些端口圆点。

“+”只在右侧。左侧要的是“哪些节点的输出能喂给这个节点”，现在的节点列表是按来源的数据类型筛的，反过来的那一种还没有。

### 属性卡片关掉不等于取消选中

以前属性面板的关闭按钮就是取消选中。现在卡片可以单独关：节点仍然选中，工具条和“+”都还在；工具条上的“属性”按钮再打开它。换一个节点选中时卡片会重新出现，所以不会出现“面板去哪了”。

手机上反过来，默认不开。抽屉盖住大半屏还带遮罩，每选中一次节点就弹出来的话，节点旁边的工具条和“+”都被挡在后面，要先关掉才能碰。所以手机上选中节点只出现工具条，「属性」点了才出抽屉。

记的是“用户对当前选中的这个节点做的选择”（`inspectorChoice`），没有选择时桌面开、手机关。

### 节点被属性卡片盖住时挪镜头

卡片浮在画布上，选中的节点正好在它底下时就看不见了。打开卡片时如果节点（连同右边的“+”）和卡片重叠，把视口往左平移重叠的宽度。挪的是镜头，节点坐标不变。只在桌面端做：手机上抽屉后面的画布本来就有遮罩。

### 连线的粗细和深浅交给样式表

以前每条线带着行内的 `strokeWidth: 2`，样式表里“悬停和选中时加粗”的规则因此从来没有生效过。现在行内只留颜色（按数据类型），其余在 `app/globals.css`：平时 55% 不透明度，和选中节点相连（`.canvas-edge-active`）、正在运行、悬停、选中时是实色加粗。

哪些线“和选中节点相连”在 `use-flow-elements.ts` 里算，和节点一样按 id 缓存：选中状态变了，只有相关的那几条线换新对象。

### “适应画布”不放大过 100%

进入页面、点“适应画布”、自动排列之后的适应，上限都是 100%。以前只有一两个节点时会被放大到 200%，节点里的输入框大得不成比例。四周留的空也改成了按像素算：上下左右都有工具条，贴边的节点会被盖住。

“缩放至选中节点”是明确要看清某几个节点，上限 150%。

### 空画布上加第一个节点，镜头不动

React Flow 的 `fitView` 属性是“第一批节点量好尺寸后适应一次”。画布是空的时候这一次会一直留着，等到第一个节点出现才做：双击或拖进来的第一个节点刚落下，镜头就把它挪到了屏幕中间。以前拖放就有这个问题，加了双击添加之后更明显。

现在只有进入页面时画布上已经有节点（上次留下的、从旅程带过来的）才排这一次适应。为此 `canvas-content.tsx` 先读回本地存的画布，再挂 `<Canvas />`，它挂上的那一刻就知道有没有节点。

读取和导入工作流换的是一整张图，这时主动适应一次（`canvas-events.ts` 的 `requestCanvasFit`）。以前只有“页面打开后还没加过节点”时读取才会碰巧适应。

### 工作流菜单的对话框状态放在常驻组件里

菜单一关就卸载，菜单项自己记不住“正在确认要不要替换画布”。`WorkflowMenu` 常驻，它的状态是一个可辨识联合（`confirmNew` / `nameBeforeNew` / `load` / `confirmLoad` / `confirmImport` / `confirmClear`），同一时刻只有一个对话框。以前这段逻辑分散在四个按钮组件里，每个按钮“点了就把自己换成对话框”。

保存和另存为仍然交给 `WorkflowSaveController`（它还管着 Ctrl+S）。

那几个自己铺满屏幕的对话框通过 portal 挂到 `body`：祖先只要有 `transform` 或 `backdrop-filter`，`position: fixed` 就会改成相对那个祖先定位。

从菜单项打开对话框时焦点要补一次。菜单开着的时候焦点被它圈在自己里面，保存对话框挂上时对输入框的 `focus()` 会被拉回菜单；菜单随后卸载，焦点就落到了 `body` 上。所以在菜单关闭的回调里，如果页面上有对话框而焦点不在里面，把焦点放到对话框里标了 `data-autofocus` 的元素上（没有就是对话框本身）。用 Radix 做的确认框不受影响，它们之间会互相让出焦点。

### 右键菜单用现成的下拉菜单

`CanvasContextMenu` 把下拉菜单的触发按钮换成一个钉在鼠标位置、看不见的锚点，方向键、首字母、Esc、边缘避让都是现成的，不用为它再引一个依赖。菜单是非模态的：菜单开着时在别处再点右键，会直接在新位置重开。

### 自动连线先看运算结果

`getAutoConnectPlan`（节点库里“加在已选节点后并连接”用的）以前把“能往外连的参数”排在运算结果前面。编码解码这类节点的“编码方式”“模式”也能往外连，于是从它后面加一个哈希节点，连过去的是字面的 `base64`，不是编码后的文本。现在结果在前。“+”用的是同一个原则（`getPrimaryOutput`）。

## 顺手修掉的问题

### 给设计令牌加透明度的类名不产生任何样式

`tailwind.config.ts` 里 `md-*` 颜色是裸的 `var(--md-sys-color-…)`。Tailwind 3 没法给这种值套透明度，`bg-md-surface-container/95`、`hover:bg-[var(--md-sys-color-on-surface)]/[0.08]`、`bg-[var(--md-sys-color-scrim)]/50` 这样的类名**整条规则都不生成，也不报警告**。

画布里受影响的：

- 保存、读取、新建确认、通用确认四个对话框**没有遮罩**，后面是原样的画布；
- 所有按钮的悬停底色、危险操作的悬停色、提示条的描边都没有；
- 旧工具条的“半透明底色”其实是完全透明，只剩一层模糊。

这次把画布目录里的 50 处都换成了能生效的写法，并在 Tailwind 配置里加了两个状态层颜色：

```
hover:bg-md-hover      /* on-surface 8% */
active:bg-md-pressed   /* on-surface 12% */
```

浮动面板改用不透明的 `bg-md-surface-container`，不再需要背景模糊。遮罩用 `bg-black/50`。

**全站还有约 160 处同类写法**（52 个文件，包括顶栏的 `bg-[var(--md-sys-color-surface)]/95`、通用按钮的悬停态、首页的几处描边）没有动。它们不能简单地“让它生效”：有些元素本身有底色，悬停层一旦生效会把底色整个换掉。需要逐个看，见下面“留给以后”。

### 其他

- 快捷键处理读 `event.target.closest`，事件直接派发在 `window` 上时会抛错。现在先判断目标是不是元素。
- 工作流名称按钮的读屏名称改成显式的 `aria-label`（“工作流 · 日报 · 有未保存的修改”），不靠各家读屏怎么拼接里面的几段文字。
- 导出、导入的结果以前显示在节点库折叠区里的一行小字，现在是全局提示；导入失败用错误样式。

## 留给以后

- **全站的透明度类名**（上面那 160 处）。要么逐个改成能生效的写法，要么把令牌换成 Tailwind 能套透明度的形式；后者会改动每一条用到令牌的规则，并且让不支持 `color-mix()` 的旧浏览器丢掉全部颜色，所以没有在这次顺手做。
- **节点里的参数名和选项仍是英文**（Input、Encoding、Decode），和旅程页是同一个问题。
- 开发模式下 Next 的指示器会盖住左下角的撤销按钮；正式构建里没有。
